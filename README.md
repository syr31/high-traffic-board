High-Traffic Board System

1. 프로젝트 개요 및 목표
본 프로젝트는 대규모 사용자 트래픽과 데이터 증가 환경에서 일관된 성능과 확장성을 보장하는 게시판 시스템을 구축하는 것을 목표로 합니다. MSA(Microservice Architecture) 기반의 서비스 분리 및 Event-Driven Architecture (EDA)를 주요 설계 요소로 채택하여 고가용성 환경을 구현했습니다.

2. 아키텍처 및 핵심 기술 스택
백엔드: JAVA, Spring Boot, Spring Data JPA를 사용하여 안정적이고 엔터프라이즈 환경에 적합한 시스템을 구축했습니다.

주 데이터 관리: MySQL을 활용하여 게시글, 댓글 등 핵심 데이터의 트랜잭션 및 무결성을 안전하게 보장하며, 데이터베이스의 분산을 고려하여 설계되었습니다.

비동기 통신: Kafka를 활용하여 서비스 간 비동기 통신 (EDA)을 구현하고, 이벤트 유실 방지를 위한 메시지 브로커로 사용했습니다.

성능/캐싱: Redis를 활용하여 조회수 집계, 인기글 랭킹 처리 (Sorted Set 자료구조 활용), 그리고 조회 최적화 캐시 등에 사용되었습니다.

3. 고성능 및 확장성 확보 전략
프로젝트의 핵심 목표 달성을 위해 다음의 실무 패턴들을 적용했습니다.

1. 데이터 일관성 및 무결성
Transactional Outbox 패턴: DB 트랜잭션(데이터 변경)과 Kafka 이벤트 전송을 단일 트랜잭션으로 묶어, 이벤트 유실 없이 데이터의 최종적 일관성을 보장합니다.

카운트 데이터 분리: SRP(단일 책임 원칙)에 따라, 좋아요 수/댓글 수 등 자주 갱신되는 카운트 데이터를 원본 테이블과 분리하여 관리함으로써, 동시 쓰기 요청에 의한 Record Lock (리소스 경합) 발생을 원천적으로 차단했습니다.

2. 확장성 및 유연성
Keyset Pagination (커서 기반): 게시글 목록 조회 시 OFFSET 대신 마지막 조회 데이터의 고유 키를 기준점(Cursor)으로 사용하여, 뒷 페이지 조회 성능 저하 문제를 근본적으로 해결하고 페이지 위치와 관계없이 일관된 쿼리 응답 속도를 유지합니다.

논리적 샤드 및 Router: 논리적 샤드 개념을 도입하고 Shard Router가 라우팅을 전담하게 하여, 물리적 DB 서버(샤드)의 확장이나 변경이 Client 애플리케이션 코드에 영향을 주지 않도록 시스템의 유연한 확장성을 확보했습니다.

3. 성능 최적화
캐시 최적화 (Request Collapsing): Redis와 분산 락을 활용하는 Request Collapsing 기법을 적용하여, 캐시 만료 시 발생하는 다수의 중복 요청 트래픽이 원본 서버로 전달되는 것을 방지하고 성능을 최적화했습니다.
